## 동작 원리
# 1) 선택 정렬 (Selection)

* **비유**: 운동장에서 줄 세울 때, 선생님이 **남은 사람들 중 제일 작은 키**를 골라 **맨 앞**에 세움. 이걸 계속 반복.
* **작동 예**: [4, 3, 1, 2] → (가장 작은 1을 앞) [1, 3, 4, 2] → (다음으론 2) [1, 2, 4, 3] → …
* **포인트**: 방법이 **아주 단순**하지만 비교를 많이 해서 **느릴 수 있음**. 대신 **바꾸는(스왑) 횟수는 적음**.

# 2) 삽입 정렬 (Insertion)

* **비유**: 손에 든 **카드를 정렬**한다고 생각. 새 카드(현재 값)를 **알맞은 자리까지 왼쪽으로 쏙** 끼워 넣음.
* **작동 예**: [4, 3, 1, 2]
  ① 3을 4 앞에 → [3, 4, 1, 2]
  ② 1을 맨 앞으로 → [1, 3, 4, 2]
  ③ 2를 1과 3 사이로 → [1, 2, 3, 4]
* **포인트**: **거의 정렬된 상태**에서는 **매우 빠름**. 작은 데이터에 특히 좋음.

# 3) 병합 정렬 (Merge)

* **비유**: 종이를 계속 **반으로 접어(쪼개서)** 한 장씩이 되면, 두 장씩 펼치며 **작은 것부터 합쳐** 나감.
  즉, **작은 두 줄을 큰 한 줄로 합치는** 작업을 반복.
* **작동 예**: [4, 3, 1, 2] → [4,3]·[1,2]로 나눔 →
  [4,3]을 정렬해 [3,4], [1,2]는 이미 [1,2] →
  두 줄을 합치며 작은 것부터 꺼내서 [1,2,3,4].
* **포인트**: **항상 안정적이고 일정하게 빠름**. 대신 **임시 그릇(새 배열)**이 필요.

# 4) 퀵 정렬 (Quick)

* **비유**: **기준 막대(피벗)**를 하나 세우고, **작은 애들은 왼쪽, 큰 애들은 오른쪽**으로 나눔.
  양쪽 줄에서도 다시 기준을 세워 **계속 나눠** 정렬.
* **작동 예**: [4, 3, 1, 2], 기준=3 →
  왼쪽 [1,2] / 가운데 3 / 오른쪽 [4] →
  왼쪽[1,2]도 같은 방식으로 정렬 → [1,2,3,4].
* **포인트**: **평균적으로 가장 빠름**. 다만 **기준을 못 고르면 느릴 수 있음**.

---

## 언제 어떤 걸 쓰면 좋을까?

* **데이터가 거의 정렬됨 / 크기가 작음** → 삽입 정렬
* **같은 값의 기존 순서를 유지해야 함** → 병합 정렬(안정적)
* **보통의 일반적인 상황, 빠른 평균 성능** → 퀵 정렬
* **아주 단순하고 교환(쓰기) 횟수를 줄이고 싶을 때** → 선택 정렬

## 한눈에 비교

| 알고리즘  | 평균 시간          | 최악 시간          | 공간          | 안정성    | 특기/역할                        |
| ----- | -------------- | -------------- | ----------- | ------ | ---------------------------- |
| 선택 정렬 | O(n²)          | O(n²)          | O(1)        | 불안정    | 교환 횟수 최소, 교육/쓰기 비용 큰 환경      |
| 삽입 정렬 | O(n²)          | O(n²)          | O(1)        | **안정** | **작은/거의 정렬** 데이터, 하이브리드용 소구간 |
| 병합 정렬 | **O(n log n)** | **O(n log n)** | O(n)        | **안정** | 일관된 성능, **안정성 필요**/외부 정렬     |
| 퀵 정렬  | **O(n log n)** | O(n²)          | O(1) (재귀스택) | 불안정    | 평균적으로 가장 빠른 **범용 in-place**  |

## 실제 작동 

입력 배열 **[3, 1, 12, -11, 10, 0]** 

# 선택 정렬 (Selection)

* 원리: 남은 구간에서 **최솟값을 찾아** 맨 앞과 교환.
* 진행(바깥 루프 한 번 = 한 단계):

1. 최소=-11 ↔ 3 교환 → **[-11, 1, 12, 3, 10, 0]**
2. 최소=0 ↔ 1 교환 → **[-11, 0, 12, 3, 10, 1]**
3. 최소=1 ↔ 12 교환 → **[-11, 0, 1, 3, 10, 12]**
4. 최소=3 (교환 없음) → **[-11, 0, 1, 3, 10, 12]**
5. 최소=10 (교환 없음) → **[-11, 0, 1, 3, 10, 12]** ✅

# 삽입 정렬 (Insertion)

* 원리: 왼쪽은 항상 정렬됨. **현재 값**을 왼쪽으로 밀어 **알맞은 자리에 끼우기**.
* 진행(현재 값 하나 삽입 = 한 단계):

1. 1 삽입 → **[1, 3, 12, -11, 10, 0]**
2. 12 삽입(그대로) → **[1, 3, 12, -11, 10, 0]**
3. -11 삽입 → **[-11, 1, 3, 12, 10, 0]**
4. 10 삽입 → **[-11, 1, 3, 10, 12, 0]**
5. 0 삽입 → **[-11, 0, 1, 3, 10, 12]** ✅

# 병합 정렬 (Merge)

* 원리: **분할 → (각각 정렬) → 병합**. 새 배열을 만들어 합침.
* 분할: [3,1,12] | [-11,10,0]

  * 왼쪽: [3] & [1,12] → 병합 → **[1,3,12]**
  * 오른쪽: [-11] & [10,0]→[0,10] → 병합 → **[-11,0,10]**
* 최종 병합: [1,3,12] ⊕ [-11,0,10] → **[-11, 0, 1, 3, 10, 12]** ✅
  *(원본은 바뀌지 않고, 정렬된 “새 배열”을 반환)*

# 퀵 정렬 (Quick)  *(피벗=구간의 마지막 값, Lomuto 파티션)*

* 원리: **피벗(0)** 기준으로 작음/큼으로 **분할** → 양쪽을 재귀 정렬.
* 1차 분할(pivot=0): [3,1,12,-11,10 | 0] → **[-11, 0, 12, 3, 10, 1]** (피벗 위치=1)
* 오른쪽 구간(pivot=1): [12,3,10 | 1] → **[-11, 0, 1, 3, 10, 12]** (피벗 위치=2)
* 남은 [3,10,12] 정렬(이미 부분 정렬) → **[-11, 0, 1, 3, 10, 12]** ✅

---

## 최종 결과 (모든 알고리즘 공통)

**[-11, 0, 1, 3, 10, 12]**

## GC란? (아주 쉽게)

컴퓨터 메모리에 **쓰다 버린 물건**(더 이상 쓰지 않는 데이터)이 쌓여요.
**GC(가비지 컬렉션)** 는 자동 **청소기**예요. “이제 아무도 안 잡고 있는(참조하지 않는) 데이터”를 찾아서 치웁니다.

* **누가 치워?** 자바스크립트 엔진(V8)이 자동으로.
* **언제 치워?** 딱 정해진 때가 아니라, 필요할 때 가끔. (메모리가 꽉 차려 하거나 엔진이 한가할 때 등)
* **우리가 직접 치울 수 있어?** 기본은 아니고, `node --expose-gc`로 실행하면 `global.gc()`로 **지금 한 번 청소해!** 라고 요청 가능. (측정용으로만 써요)

## “더 이상 안 쓰는 데이터”가 뭔데?

변수/배열/객체를 **가리키는 손(참조)** 이 하나도 없을 때예요.
예를 들어:

```js
let a = [1,2,3]; // a가 배열을 가리킴
a = null;        // 이제 그 배열은 아무도 안 붙잡음 → 청소 대상
```

## 왜 **메모리 변화가 음수**로 나와?

우리가 보여주는 값은 **전후 차이(Δ = 정렬 후 - 정렬 전)**예요.

* 정렬 사이에 **GC가 더 많이 청소**했다 → 정렬 후 메모리가 **더 작음** → **음수(–)** 로 보임.
* 특히 **선택/삽입/퀵**은 새 배열을 거의 안 만들라 **청소 효과**가 더 크게 보일 수 있어요.
* 반대로 **병합 정렬**은 새 배열을 만들어 돌려주니까 측정 시점에 메모리가 **잠깐 늘어** **양수(+)** 로 보이기 쉽습니다.

> 포인트: **Δ는 “최대 얼마나 썼는가”가 아니라 “전후 순변화”**라서 음수가 나와도 완전 정상!

## 그럼 “얼마나 썼는지”는 어떻게 보나?

* **피크 메모리(관측 최대치)** 를 같이 보세요.
  벤치마크 표의 “피크 메모리(대략)” 컬럼이 그거라, **병합 정렬이 더 큰 값**으로 나타나는 경향이 있어요.

## 한 줄 요약

* GC = **자동 메모리 청소기**
* 아무도 안 쓰는 데이터 → **자동으로 제거**
* 전후 차이(Δ)가 **음수**인 건 **청소를 더 많이 해서** 그런 것
* 진짜 사용량 감은 **피크 메모리**로 보기!
